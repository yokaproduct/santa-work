## 3. 画像の差し替え時の注意

### 3.1 作り方の目安

| # | 項目 | 目安 |
|---|---|---|
| 1 | 書き出し解像度 | Canvasは横1080基準。最近のiPhoneの実画面は横1170〜1290px程度なので、**表示サイズの1〜1.25倍**で書き出せば十分。**2048pxを超えない**(現在のインポート設定の最大値) |
| 2 | 背景の縦長対応 | 基準は1080×1920(9:16)だが、iPhoneは約9:19.5。**1080×2340 以上で描き、重要な絵柄は中央の1080×1920に収める**。伸ばすか切り取るかの表示方式は開発チームに確認(Q-13) |
| 3 | 文字 | **画像に文字を焼き込まない**(日英の2言語対応のため)。ロゴは例外として別途判断(Q-11) |
| 4 | 着色される素材 | コードやPrefabで色を乗算するもの(M5の形、ボタン枠、バー)は**白〜明るい灰色で描く**。**M1在庫アイコン、M5の完成箱画像(赤/青/~~黄~~緑)、★M3そり統合画像、★HUD背景は完成画像方式のため対象外**(色・模様まで含めて完成させた絵をそのまま出す。素材未設定時のプレースホルダ色のみ例外) |
| 5 | 色 | **色だけに頼って区別させない。赤×緑を同じ画面で並べない**(M2の朱と緑は明度差を十分に取る)。**★例外(2026-09-16): M5の色カテゴリ(赤・青・緑)は、模様(赤=ハート柄 / 青=丸柄 / 緑=四角柄)の描き込みを必須条件として赤と緑を並べてよい。**模様を省いた絵・白黒にすると模様が見分けられない絵は使わない(`23_MicroGame_Wrap.md` §5.2)。**M1など他の種目には例外を広げない** |
| 6 | 点滅 | 演出で**毎秒3回を超える点滅を作らない** |
| 7 | 形式 | PNG(透過が要るものは32bit)。9-slice素材は**角の半径ぶん以上の余白**を持たせ、インポート後に Sprite Editor で Border を設定する |
| **8** ★ | **透過なしの仮画像(2026-09-16)** | **HUD背景・M1在庫アイコン10点・M5箱3色+ゴミ・M3そり統合画像10点は、いまは 24bit PNG・透過なし(背景が白)。**透過版(32bit PNG、背景を透明)を**同じファイル名で上書き**する。**★2026-09-16 developer対応: 25枚とも Sprite(2D and UI)・`alphaIsTransparency = 1` でインポート済み。透過版を同名で上書きすればそのまま反映される。**上書き後に透過が効かない・縁に白いにじみが出る場合だけ、インポート設定(Alpha Source 等)の確認を developer に依頼する |

### 3.2 やってよいこと・いけないこと

| # | 内容 |
|---|---|
| 1 | **同じファイル名で上書き(エクスプローラー等で置き換え)すれば、`.meta` のGUIDが保たれ、Prefab・SO側の参照はそのまま。**差し替え方法「A」はこれ |
| 2 | **Unity上でいったん削除して入れ直す / Unityの外でファイル名を変える、はしない。**GUIDが変わって参照が切れる(名前を変えるならUnityのProjectウィンドウで行う) |
| 3 | **`UI_SolidRect.png` は上書きしない。**約20か所の Image が共有しているため、1枚をデザイン画像にすると全部が同じ絵になる。**新しいファイルを作り、必要な Image にだけ割り当てる**(差し替え方法「B」) |
| 4 | Filled型のバー(T1/T2バーのフィル、M3メーターのフィル)は**Spriteを「なし」にできない**(`fillAmount` が効かなくなる。決定ログ 実-5) |
| 5 | Source Image の割り当ては**レイアウト値ではない**が、**「Set Native Size」を押すと `sizeDelta` が変わる**ので押さない。位置・サイズの変更が必要ならディレクターの判断で行う(CLAUDE.md「UIレイアウトの取り扱い」) |
| 6 | 9-slice の Border や Pixels Per Unit は `.meta` に保存される。**画像の縦横サイズを変えて上書きした場合は Border を設定し直す** |
| 7 | **Image に乗算色が入っている要素がある**(例:`FlagImage` 灰色0.92、`LetterBackground` 薄い黄、~~`CardInner` クリーム~~ **`CardInner` は ★2026-09-17 時点で白(クリームからの変更。ディレクター確認中)**、`StockCard*` 赤)。絵の色をそのまま出す場合は Image色を白にする必要がある(色はレイアウト値ではないが、見た目の判断なのでディレクター確認) |
| 8 | 仮置きの識別用テキスト(~~M1 `DebugLabel`~~ **★2026-09-17 削除済み**、M5 `ChuteSampleLabel` / `DebugLabelText`、M5の「ごみ」表示)は、**本番素材を入れても自動では消えない**。非表示にするのは developer 対応 |
| 9 | 差し替え方法「C」の素材は **ScriptableObject**(`Assets/Settings/**`)の欄に入れる。Prefabを触らずに済む |
| 10 | 差し替え方法「D」の素材は、**絵を置いただけでは画面に出ない**。取りまとめ役経由で developer へ依頼する |

### 3.3 世界地図(`WorldMap.png`)を描き直すときの条件

**タップ判定は「タップした位置の色」で地域を決めている**(`WorldMapHitTester`)。そのため普通の画像より条件が多い。

| # | 条件 | 守らないと起きること |
|---|---|---|
| 1 | **6地域の塗り色を今と同じにする**(アジア=赤系 / ヨーロッパ=青系 など、現ファイルの色) | 判定用の代表色(`regionColors`。現ファイルから採った値)と合わず、**押しても反応しなくなる**。色を変えるなら developer に代表色の取り直しを依頼 |
| 2 | **塗りはグラデーション・影・テクスチャを付けない単色** | 判定のしきい値(RGB距離16)を超えて取りこぼす |
| 3 | 海は白、輪郭線は地域色と十分に違う色 | 海・線の上が地域として反応してしまう |
| 4 | **縦横比 16:9 を保つ**(表示枠 1080×608) | 絵が歪む(判定は相対座標なので壊れないが見た目が崩れる) |
| 5 | 同じファイル名で上書き | インポート設定の **Read/Write Enabled**(判定に必須)が保たれる |
| 6 | **国境線・国名は描かない。州の区分線だけ** | 係争地域の帰属を表明することになる(配信停止・削除要求のリスク) |
| 7 | 小さい地域(ヨーロッパ・オセアニア)は実際より大きく | 押しにくい。**ヨーロッパは現状 縦が基準に届いていない**(決定ログ) |
