## 1. 目的 / この種目の役割

**国旗と国名のラベルが貼られた荷物を見て、世界地図の正しい地域(州)をタップして仕分ける。**

- 使う知識: 地理(国 → 大陸)
- 業務提示ワード: **「とどけろ!」**(`micro.address.prompt`)
- 操作: **世界地図の地域をタップ(1回で確定・取り消しなし)**
- 1件 = 荷物1個(`questionsPerUnit = 1`)

**4種で最も「説明がいらない」種目**(設計原則5を最もよく満たす)。荷物にラベルが貼ってあり、地図を押すだけ。
**チュートリアルに入れる第一候補。**

**難易度は設計しない。** 国の認知度は人によって違うので、それだけでばらつきが再現できている。
同じ「フランス」でも知っている人には一瞬、知らない人には難問になる。**難易度が出題側ではなくプレイヤー側にある。**

### 1.1 学習の担保方針(**プロジェクト全体に効く基準**)

> ディレクターの判断: 「何が正解か分からなければ、**あとで自分で調べられるような内容にすればよい。**
> 国名は調べれば分かるし、今の時代 画像検索もあるからどうとでも調べられる」

ここから2つが決まっている。

1. **不正解時に荷物を正解の地域へ飛ばさない。** 押した地域が赤く沈むだけ。**正解は一切示さない。**
2. **国名は必ず表示する。** 調べる取っかかりを画面に残す必要があるため。**「国旗のみ表示」は確定的に不採用。**

### 1.2 差し込まれる場所

`Screen_GamePlay` の `MicroGameSlot`。HUD・12秒バー・業務提示・判定演出は `Screen_GamePlay` 側が持つ。

## 4. 処理内容(`MicroGameBase` の実装)

### 4.1 `Prepare(MicroGameContext context)`

```
1. context.Definition.questionSource を CountryTable にキャスト
2. 1問目の Country を取り出す(セッション開始時にシャッフル済み。共通仕様 §8.7)
3. FlagImage に flagSprite を設定(未設定ならプレースホルダ)
4. CountryNameText に現在の言語の国名を流し込む
5. ★セッション状態(AddressSessionState)を取得する(§4.7)。
   ~~6地域の RegionCounterText に累積数を反映する~~ ★2026-09-17: カウンタ表示の廃止に伴い、表示への反映は行わない
6. 全地域の当たり判定を無効化(まだ押せない)
7. ★この時点で荷物と地図は画面に見えている
```

### 4.2 `Begin()`

```
1. 全地域の当たり判定を有効化
```

### 4.3 地域をタップしたとき

```
1. 押された地域が「輪郭の内側」かを判定
   ・輪郭の外(海・区分線)→ ★何もしない。SEも鳴らさない。判定もしない
2. se_tap を再生し、押下演出(正誤共通)を出す
   ★2026-09-17: 押下演出は「押した地域の拡縮」だけ(§3.1 の実装表)。タップ位置のマーカー(TapFeedbackImage)は削除済み。出さないこと
3. 全地域の当たり判定を無効化(連打による二重回答を防ぐ)
4. 正誤を判定(country.regionId == 押した地域のID)
   ・正解 → 正解演出 + 該当地域の累積数を +1(セッション状態を更新。★2026-09-17: 画面には表示しない)+ OnUnitCleared を発火
   ・誤答 → 押した地域が赤く沈む + OnMissed を発火。★累積数は増やさない
5. 成立件数を数える
   ・3件に達した → OnAllUnitsCleared を発火して終了
   ・達していない → 次の荷物を用意し、当たり判定を有効化
```

**次の荷物への切り替えは即座に行う(待ち時間ゼロ)。**

### 4.4 `SetPaused(bool paused)`

```
paused = true  : 当たり判定を無効化。演出アニメーションを止める
paused = false : Begin() 済みなら当たり判定を有効化
```

### 4.5 `Finish(MicroGameFinishReason reason)`

```
1. 当たり判定を無効化
2. 進行中の演出を即座に完了状態にする
3. ★OnUnitCleared / OnMissed を発火しない
```

### 4.6 `GetSummary()`

```csharp
new MicroGameSummary {
    UnitsCleared      = 正解した荷物の数(0〜3),
    UnitsMissed       = 誤答した荷物の数,
    QuestionsAnswered = UnitsCleared + UnitsMissed,
}
```

### 4.7 ★セッションをまたぐ累積カウンタ(**共通仕様の契約に不足があった箇所**)

> **★2026-09-17 ディレクター指示・developer 実装: 地図上の数字表示(`RegionCounterText`)は廃止した。累積値は表示しないが、保持と加算は続ける。**
>
> | 項目 | 2026-09-17 以降 |
> |---|---|
> | `AddressSessionState.DeliveredPerRegion` | **残す。正解のたびに該当地域を +1 する(従来どおり)** |
> | `GetOrCreateState` での取得・セッションをまたぐ引き継ぎ・セッション開始時の破棄 | **従来どおり**(本節の下記の記述は有効) |
> | 画面への表示(6地域の数字・+1 時のパンチ演出) | **無し**。`RefreshAllRegionCounters` / `UpdateRegionCounterText` / `RegionRefs.regionCounterText` は削除済み |
> | 保持する理由 | **将来、結果画面などで「どこへ何個届けたか」を見せる演出の余地を残すため**(§8-5 の12月候補) |
>
> 以下の本文で「カウンタを表示する」「反映する」と書いている箇所は、**「累積値を保持する」と読み替える**こと。
> なお `AddressSessionState` は現在、出題プール(`Pool`)と地図の判定表(`MapLookup`)もセッションをまたいで保持しており、仕組み自体は引き続き必要。

**問題**: 地図の累積カウンタは「1プレイを通じて」蓄積される。しかし
**`MicroGame_Address` のPrefabは、M2が終わるたびに `Destroy` される。**
つまり**Prefabの中にカウンタを持つと、次にM2が出たときに0に戻ってしまう。**

**解決**: **共通仕様 §4.3 の `MicroGameContext` に `GetOrCreateState<T>(factory)` を追加した**(2026-09-08 確定)。

```csharp
public readonly struct MicroGameContext
{
    // …既存のフィールド…
    /// ★この種目がセッションを通じて保持したい状態を取得する。
    /// 無ければ factory で生成して保持し、次に同じ種目が出たとき同じインスタンスを返す。
    /// ★これが State への唯一の読み書き経路。
    public T GetOrCreateState<T>(Func<T> factory) where T : class, IMicroGameSessionState;
}

/// M2の状態
public class AddressSessionState : IMicroGameSessionState
{
    public Dictionary<string, int> DeliveredPerRegion = new();  // "asia" → 5
}
```

**M2 の `Prepare()` での使い方**

```csharp
var state = context.GetOrCreateState(() => new AddressSessionState());
// 1回目のM2 → 新規生成して保持される
// 2回目のM2 → 1回目と同じインスタンスが返る(累積カウンタが引き継がれる)

// ~~6地域の RegionCounterText に state.DeliveredPerRegion を反映する~~
// ★2026-09-17: 表示はしない。state.DeliveredPerRegion は保持するだけ
```

- **`GameSessionController` は中身を知らない。** `definition.id` をキーにした辞書で持ち回るだけ。
  **これにより、新種目が独自のセッション状態を持ちたくなっても共通側のコードを変えずに済む。**
- 正解時は `state.DeliveredPerRegion[regionId] += 1` を更新する(~~してから表示に反映する~~ ★2026-09-17: 表示には反映しない)。
- **セッション終了(`Screen_Result` へ遷移)時に破棄する。**「もう一回」では初期化される。

> **【2026-09-08 修正の経緯】初版は `IMicroGameSessionState State { get; }` というゲッターだけを定義しており、
> 「ミニゲーム側が生成して入れる」と書いていたが、`MicroGameContext` は readonly struct のため
> 「入れる」操作が存在しなかった。**
> **このままだと1回目のM2で状態を書き込めず、累積カウンタに永久に何も貯まらない。**
> developer の指摘により `GetOrCreateState` に修正した。**取得と生成が1操作になったので、
> 「入れ忘れ」も「二重生成」も構造的に起こらない。**

> **★`GameSessionController` が常設サービスになった**(2026-09-08 決定)ため、

## 6. 出題する国の選定基準

### 6.1 大陸区分の典拠(確定)

**日本の小学校社会科(学習指導要領)の6州区分。** アジア / ヨーロッパ / アフリカ / 北アメリカ / 南アメリカ / オセアニア。
**あそびかた画面への明記はしない**(区分そのものが一般的なため)。

**英語版でも問題ない。** 英語圏の標準は7大陸(6州 + 南極)だが、**南極を出題しない**
(子どもがいないのでサンタ業務として自然に除外できる)ため差が表面化しない。
北米と南米を分ける点は日本と英語圏で一致している。

### 7.1 国旗素材の制作条件(ディレクター向け)

- **比率を原典どおりに保つ**(スイス1:1、ネパール非長方形などの例外あり)。**枠に合わせて引き伸ばさない**
- **国章ありの正式版を使う**(**メキシコ**・スペイン等。簡略版は不正確または別国の旗になる)
- 配色は原典どおり
- 表裏でデザインが異なる国(パラグアイ)は表面
- **影・光沢・はためきエフェクトを付けない**
- **必ずパブリックドメイン / CC0の正確なデータ。生成AIで国旗を描かせない**
- 日本語の国名表記は**外務省表記に準拠**

### 7.2 世界地図素材の制作条件(ディレクター向け)

1. **6地域をそれぞれ別の画像として書き出す。** 1枚のフラット画像では地域ごとの当たり判定・色の出し分け・
   ~~カウンタ表示~~ができない(★2026-09-17: カウンタ表示は廃止。★2026-09-10 以降の実装は1枚絵 + 色キー判定。冒頭の注記を参照)
2. **小さい地域を実際の面積比より大きくデフォルメする。** 当たり判定が輪郭そのものになるため、
   **輪郭の大きさ = 押しやすさ**。**ヨーロッパとオセアニアが 160×160px(共通仕様 §7.5)を下回るおそれがある**
3. **州の区分線を描く**(別レイヤーが望ましい)。**国境線は描かない。地図上に国名も入れない**
4. 区分線が通る場所は6州区分の解釈が割れる場所と一致する(ウラル山脈 / スエズ / パナマ地峡 /
   インドネシア周辺)が、**これらにまたがる国はすべて出題から除外している**ため、
   線の引き方が正誤に影響することはない。**教科書の区分に沿って引けば足りる**

## 10. 数字の整合性

| 項目 | 値 |
|---|---|
| 1件 | 荷物1個 |
| 1ミニゲームの必要件数 | **3件** |
| `questionsPerUnit` | **1** |
| 1ミニゲームの最大スコア | **300点 × 倍率** |
| 1ミニゲームの最大コンボ | **3** |
| 基準時間 | **12秒** |
| プロトタイプの国数 | **10か国**(6地域すべてを最低1か国ずつ) |
| 地図の地域数 | **常に6。問題によって変えない**(設計原則2) |
| 1ミニゲームで消費しうる最大問数 | **上限なし**(3件正解するまで供給)。10問を使い切ったら**先頭に戻って繰り返す** |

> **プールの枯渇はM2で最も起きやすい。** タップ1回で即判定されるため、適当に押せば1〜2秒で1問消費し、
> 12秒あれば6問以上を簡単に使い切る。10問に増やしたことで実際にはほぼ到達しないが、
> **`ShuffledPoolCursor` の「先頭に戻る」実装は必須。**
