## 1. 画面の目的

**アプリ起動直後の初期化とUMP同意フォームだけを担当する。ロゴは表示しない。**

> **【2026-09-07 ディレクター決定】自作ロゴは `Screen_Boot` から `Screen_Title` へ移した。**
> **Unityライセンスは Personal のため、Unityロゴのスプラッシュが強制表示され無効化できない**(§6)。
> **自作ロゴをここに置くとロゴが二重に出る**ので、`Screen_Title` に一本化した。
>
> **この変更で、前回指摘した2つの問題が同時に消えた:**
> - **㊳「`Screen_Boot` の最低表示時間が未定義」** → **ロゴを見せないので最低表示時間の概念自体が不要**(§4.3)
> - **「Bootのロゴがゲームロゴかスタジオロゴか未定」** → **論点ごと消滅**

**この画面はできるだけ短いほうがよい。** 見せるものが何も無いため、
**初期化が終わり次第、即座に `Screen_Title` へ進む。**

### 1.1 遷移元 / 遷移先

| | 画面 | 条件 |
|---|---|---|
| 遷移元 | (アプリ起動) | 常にここから始まる |
| **遷移先** | **`Screen_Title`** | **常に。分岐は無い** |

> **`Screen_Tutorial` は廃止された**(`99_廃止_Screen_Tutorial.md`)。
> **初回起動時の分岐が消え、この画面の役割は単純になった。**
> 初回の案内は `Screen_ModeSelect` が担う。

**`Screen_Boot` へ戻ってくる経路は存在しない。** 一度出たら二度と表示されない。

## 4. 処理内容

### 4.1 初期化の順序(★この順序が仕様)

```
[1] Application.targetFrameRate の設定 / Screen.sleepTimeout の設定
[2] SaveManager.Load()
     ・PlayerPrefs から全キーを読む
     ・santa.saveVersion を見てマイグレーションを行う(§4.4)
[3] 言語の決定
     ・santa.language が空 → Application.systemLanguage を見て ja / en を決める
     ・空でない → その値を使う
     ・★UMP の同意フォームより先に決める必要がある(フォームの言語に効くため)
[4] LocalizationService.Load(言語)
[5] UiTheme / GameBalanceSettings / RankTable / MicroGameCatalog のロード
[6] AudioManager の初期化(音量を SaveManager から反映)
[7] 広告まわりの初期化(§4.2)★非同期。Boot をブロックしない
[8] ★初期化が終わり次第、即座に Screen_Title へ切り替える(最低表示時間を設けない。§4.3)
     ・BGM を bgm_title に切り替える
     ・★分岐は無い。常に Screen_Title
```

### 4.2 広告・同意まわりの初期化(★審査に直結する)

```
[7-a] UMP(User Messaging Platform)の同意情報を要求する
[7-b] 同意フォームが必要か(EU圏など)を判定する
        ・必要 → ★同意フォームを表示する(SDK提供のUI)
        ・不要 → 何もしない
[7-c] 同意が得られた/不要と判定されたら、広告SDK を初期化する
[7-d] MaxAdContentRating を 4+ 相当に設定する(不適切な広告が出ないようにする)
[7-e] バナーのロードを開始する(表示はしない。AdDisplayPolicy に従う)
```

> **同意フォームは `Screen_Boot` の上に SDK 提供のUIとして出る。**
> Unity側の画面ではないため、`Screen_Boot` のレイアウトには影響しない。
> **ただし同意フォームが出ている間、`Screen_Boot` は次の画面へ進んではならない。**

> **【2026-09-07 更新】前回指摘した㊲(同意フォームと初回チュートリアルの順序)は、
> チュートリアル廃止と自作ロゴの移管によって大幅に軽くなった。**
>
> | | 旧 | **新** |
> |---|---|---|
> | 初回起動の導線 | Unityロゴ → 自作ロゴ → 同意フォーム → チュートリアル → タイトル(**5段**) | **Unityロゴ → 同意フォーム → タイトル → 選択画面(4段。うちUIは2枚)** |
>
> **ただし「起動直後にいきなり同意フォームが出る」ことは変わらない**(EU圏のみ)。
> 日本・米国での配信では同意フォームが出ないため、**実質は「Unityロゴ → タイトル」だけになる。**

> **⚠ 未定義(§7-2): ATT(App Tracking Transparency)を出すか。**
> ストア審査文書は「**非パーソナライズ広告のみで開始することを推奨**(ATT画面が不要になり10月末に効く)」
> としているが**未決**。パーソナライズ広告を使うなら ATT の前置き画面 + OSダイアログがここに増える。

### 4.3 最低表示時間 —— **設けない**(2026-09-07 変更)

> **ロゴを移管したことで、`Screen_Boot` には見せるものが何も無くなった。**
> **したがって最低表示時間は設けない。初期化が終わり次第、即座に `Screen_Title` へ進む。**

- **前回定義した「最低表示時間 1.0秒」は撤回する。** ロゴを見せないなら「ちらつく」対象が存在しない。
- 初期化が **1.0秒を超えた場合のみ** `LoadingIndicator` を出す(それ以前は何も出さない)。
- **上限は設けない**(初期化が終わるまで待つ)。ただし**起動 → タイトル表示までの時間を計測してログに出す**
  (企画書 §10.6 の要件)。
- **`Background` を `Screen_Title` と同じ絵にすれば、この画面は体感上ほぼ存在しなくなる**(§2.1)。

### 4.4 セーブデータのマイグレーション

- `santa.saveVersion` が存在しない → **新規インストール**として全キーを初期値で作成し、`saveVersion = 1` を書く。
- `santa.saveVersion` が現在のバージョンより古い → **順に変換する。**
- `santa.saveVersion` が現在のバージョンより**新しい**(ダウングレード)→ **何もしない**(触ると壊す)。
  **MVPでは起こらないが、判定だけ入れておく。**

> **12月アップデートで種目が増えると、種目別統計のキーが増える。**
> キーは `santa.micro.<id>.*` で動的に作られるため、**存在しないキーは 0 として読む**設計にしておけば
> マイグレーションは不要になる(共通仕様 §10)。**この方針を `SaveManager` に明記すること。**

- **ロゴ表示時の SE は任意**(`se_screen` を流用してもよい)。

## 6. Unity のスプラッシュスクリーン —— **Personal で確定(2026-09-07)**

> **【ディレクター確認済み】Unityライセンスは Personal。
> Unityロゴのスプラッシュは強制表示され、無効化できない。**

**この事実を受けて、自作ロゴを `Screen_Boot` から `Screen_Title` へ移した。**

| | 旧(自作ロゴがBootにあった) | **新** |
|---|---|---|
| 起動導線 | Unityロゴ → **自作ロゴ** → タイトル | **Unityロゴ → (Bootは素通し) → タイトル(ここに自作ロゴ)** |
| ロゴの重複 | **あり**(2枚続けてロゴが出る) | **なし** |

- **`Screen_Boot` は Unityロゴの直後に一瞬だけ出る、実質見えない画面になる。**
- **`Screen_Title` で初めて自作ロゴが出る。**ハイスコアと一緒に見せられるので、**ロゴが情報とともに提示される**
  (単独で見せるより印象に残る)。
- **Unityロゴのスプラッシュ設定**(表示スタイル / 背景色)は Player Settings で一部調整できる。
  **背景色を `Screen_Boot` / `Screen_Title` の背景に合わせる**と、つなぎ目が目立たなくなる(§7-4)。
