## 1. 目的

**「これから始まる」という心構えを作り、指を画面に近づけさせる。**
90秒という短いセッションで、**開始直後の1問を取りこぼさせないための助走**である。長いと「もう一回」のテンポを殺すので、**リトライ時は半分に短縮する。**

### 1.1 出るタイミング(呼び出し元とプリセット)

| プリセット | 呼び出し元 | 長さ | 表示 | 1ステップ |
|---|---|---|---|---|
| `Normal` | **`Screen_Title` の「90びょう モード」**(★2026-09-17 ModeSelect を統合) | **3.0秒** | **3 → 2 → 1 → スタート!** | 0.75秒 × 4 |
| `Short` | **`Screen_Result` の「もう一回」** | **1.5秒** | **2 → 1 → スタート!** | 0.5秒 × 3 |
| `Short` | **`Overlay_Pause` の「はじめから」** | **1.5秒** | 同上 | 0.5秒 × 3 |
| `Short` | **`Overlay_Pause` の「つづける」(ポーズからの復帰)** | **1.5秒** | 同上 | 0.5秒 × 3 |
| ~~`Minimal`~~ | ~~初出カードの OK 後~~ | ~~1.0秒~~ | — | **2026-09-15 廃止。追加しないこと** |

- **値は `GameBalanceSettings` の既存フィールド**: `countdownNormal`(3.0)/ `countdownNormalStepDuration`(0.75)/ `countdownRetry`(1.5)/ `countdownRetryStepDuration`(0.5)。**新しいフィールドは不要。**
- **「スタート!」の直後に1本目の業務提示(`se_microgame_start`)が続く。**`se_start` の素材を用意するときは**0.5秒以内**にすること(「もう一回」のステップ長が0.5秒のため、業務提示の音と重ならない)。

### 1.2 表示する文字の決め方(★プリセットごとに配列を持たない)

**ステップ数 N = round(長さ ÷ 1ステップの長さ)**(最低2。既存の `PlayCountdownSteps` と同じ計算)。**i 番目(0始まり)のステップに出す文字は次のとおり。**

| 条件 | 表示 | SE |
|---|---|---|
| i < N − 1 | **数字 (N − 1 − i)** | `se_countdown` |
| i = N − 1(最後) | **「スタート!」** | `se_start` |

- `Normal`: N = 4 → **3, 2, 1, スタート!** / `Short`: N = 3 → **2, 1, スタート!**
- ディレクターが Inspector で長さを変えても、この規則で数字が自動的に決まる(例: 2.0秒 ÷ 0.5秒 = 4 → 3, 2, 1, スタート!)。
- **時間の進行(いまが何ステップ目か)を持つのは `GameSessionController` だけ。**オーバーレイは表示するだけで、自分の時計を持たない(§4.3)。

## 2. Prefab構造(初回生成時)

```
Overlay_Countdown                         stretch 全面(OverlayLayer の子として Instantiate)
├─ [CountdownOverlayRefs]
├─ [CountdownOverlayController]
├─ Blocker                                Image / stretch / 色 (0,0,0,0) / raycastTarget = true
└─ CountRoot                              anchor(0.5,0.5) / 1000×800 / グラフィックなし
    ├─ CountRing                          Image / 800×800 / 数字の背後の輪(任意。IMG-OV-01)。raycastTarget = false
    └─ CountAnim                          ★演出用ラッパー(共通仕様 §7.4.1)/ 1000×400 / CanvasGroup
        ├─ CountNumberText                TMP 「3」「2」「1」
        └─ StartText                      TMP 「スタート!」
```

- **`Blocker` は透明だが `raycastTarget = true`。**カウントダウン中のタップを完全に遮断する(HUD のポーズボタンやミニゲームに届かない)。
- **画面を暗くしない**(`Blocker` の alpha は 0)。理由は §5.1。
- **数字と「スタート!」を別の要素にする理由**: フォントサイズ400で「スタート!」(5文字)を出すと横幅が約2000pxになり画面に収まらない。**1つのテキストで自動縮小(Auto Size)すると、ディレクターがフォントサイズを調整できなくなる**ので、要素を分けて別々のサイズを持たせる。
- **`CountRing` は Sprite が無い間は `Image.enabled = false`**(白い四角が出ないように)。素材 IMG-OV-01 が入ったら有効にする。

### 2.1 レイアウト初期値(**以後ディレクターの所有物**)

| 要素 | 親 | anchor / pivot | anchoredPosition | sizeDelta | その他の初期値 |
|---|---|---|---|---|---|
| `Overlay_Countdown`(ルート) | `OverlayLayer` | (0,0)-(1,1) / (0.5,0.5) | offset 0 | 全面 | — |
| `Blocker` | ルート | (0,0)-(1,1) / (0.5,0.5) | offset 0 | 全面 | Image 色 (0,0,0,**0**)、`raycastTarget = true` |
| `CountRoot` | ルート | (0.5,0.5) / (0.5,0.5) | (0, 0) | (1000, 800) | — |
| `CountRing` | `CountRoot` | (0.5,0.5) / (0.5,0.5) | (0, 0) | (800, 800) | Sprite なし・`enabled = false`・`raycastTarget = false` |
| `CountAnim` | `CountRoot` | (0.5,0.5) / (0.5,0.5) | (0, 0) | (1000, 400) | `CanvasGroup`(alpha 0 で開始・`blocksRaycasts = false`)。scale (1,1,1) |
| `CountNumberText` | `CountAnim` | (0.5,0.5) / (0.5,0.5) | (0, 0) | (800, 400) | **フォントサイズ 400**・中央揃え・折り返しなし・白・`raycastTarget = false` |
| `StartText` | `CountAnim` | (0.5,0.5) / (0.5,0.5) | (0, 0) | (1000, 240) | **フォントサイズ 180**・中央揃え・折り返しなし・白・`raycastTarget = false` |

- **位置は画面(Canvas)の中央。**`SafeAreaRoot` の中ではない(オーバーレイは全面)。基準解像度 1080×1920 で中心は上から 960px。**`Screen_GamePlay` の HUD(上から約200px)とは重ならない**(`CountRoot` の上端は上から 560px)。
- **文字の縁取り(★必須)**: 白い文字に**暗い色の縁取り**を付ける(初期値: 色 (0.08, 0.10, 0.18)、TMP の Outline Thickness 0.2)。
  **背後が明るい GamePlay の背景(2026-09-17 時点の仮の色は (0.85, 0.90, 0.95))のときも、黒い `PromptBackdrop` のとき(§5.2)も読めるようにするため**(共通仕様 §7.7)。
  **TMP の縁取りはマテリアルの設定なので、共有マテリアルを直接変えると他のテキストにも縁取りが付く。**カウントダウン専用のマテリアルプリセットを**アセットとして事前に作って**割り当てること(実行時生成しない。CLAUDE.md)。
- **文言**: `CountNumberText` は数字をコードで流し込む(ローカライズ不要)。`StartText` は `LocalizedText`(キー案 `countdown.start`: ja「スタート!」/ en「GO!」。既存キーがあればそれを使う)。

## 4. 処理内容

### 4.1 タイムライン

**通常版 `Normal`(3.0秒)**

| 時刻 | 表示 | SE |
|---|---|---|
| 0.00 〜 0.75 | **3** | `se_countdown`(★当面無音) |
| 0.75 〜 1.50 | **2** | `se_countdown` |
| 1.50 〜 2.25 | **1** | `se_countdown` |
| 2.25 〜 3.00 | **スタート!** | `se_start`(★当面無音) |

**短縮版 `Short`(1.5秒)**

| 時刻 | 表示 | SE |
|---|---|---|
| 0.00 〜 0.50 | **2** | `se_countdown` |
| 0.50 〜 1.00 | **1** | `se_countdown` |
| 1.00 〜 1.50 | **スタート!** | `se_start` |

- **どのカウントダウンでも T1(90秒)は止まっている**(セッション開始前 / ポーズ中)。**「スタート!」の表示中も T1 は動かない。90秒はカウントダウン終了後に始まる。**
- **SE の呼び出しは既存の `PlayCountdownSteps` にある**(ステップの頭で `se_countdown` / 最後に `se_start`)。**素材が未登録の間は無音**で、登録すればコード変更なしで鳴る。

### 4.2 各ステップのアニメーション(演出値)

**ステップの長さを L(0.75秒 / 0.5秒)、ステップ内の経過時間を t とする。**動かすのは**ラッパー `CountAnim` の `localScale` と `CanvasGroup.alpha` だけ**(共通仕様 §7.4.1)。

| 区間 | `CountAnim.localScale` | `CountAnim` の alpha | 備考 |
|---|---|---|---|
| **t = 0** | 1.3 | **1**(即座に表示) | 文字を差し替え、`CountNumberText` / `StartText` の出し分けを切り替える |
| 0 〜 **0.10秒** | **1.3 → 1.0**(イーズアウト) | 1 | 「ポン」と置かれる動き |
| 0.10 〜 L − 0.10 | 1.0 | 1 | 静止 |
| **L − 0.10 〜 L** | 1.0 | **1 → 0** | フェードアウト |

| 演出値(初期値) | 値 |
|---|---|
| 登場時の倍率 | 1.3 |
| 登場の長さ | 0.10秒 |
| フェードアウトの長さ | 0.10秒 |

- **置き場所**: Inspector で変えられればよい(`CountdownOverlayController` のシリアライズフィールド、または `PromptEffectSettings` と同じく SO。developer 判断)。
- **ステップが 0.2秒より短く設定された場合**は、登場とフェードの長さをステップの半分ずつに縮める(破綻しないように)。
- **点滅の頻度**: 表示が切り替わるのは毎秒 1.33回(0.75秒)/ 2回(0.5秒)。**毎秒3回の上限(共通仕様 §3.8 制約5)を下回る** ✓。
- **オーバーレイを閉じるとき・ポーズで中断したときは、`localScale` を 1.0、alpha を 0 に戻す**(Prefab アセットを書き換えない)。

### 4.3 時間の進め方と表示の同期(★実装の要件)

- **時間を持つのは `GameSessionController` だけ。**オーバーレイは毎フレーム「いま何ステップ目で、ステップ内の経過が何秒か」を読んで表示する(業務提示の `PromptEffectPlayer` が `PhaseElapsed` を読むのと同じ方式。`10_Screen_GamePlay.md` §12.4)。
  公開の形(`CountdownStepIndex` / `CountdownStepCount` / `CountdownStepElapsed` / `CountdownStepDuration` を足す、`PhaseElapsed` を流用する等)は developer 判断。
  **★実装(2026-09-17): `IGameSessionService` に `CountdownStepIndex` / `CountdownStepCount` / `CountdownStepElapsed` / `CountdownStepDuration` を公開した。`CountdownStepIndex` はカウントダウン中だけ 0 以上で、終わると -1 に戻る。**
- **★表示条件(2026-09-17 変更): `CountdownOverlayController` は `CountdownStepIndex >= 0` のときだけ文字を出す。`Phase == Countdown` を条件にしない。**
  理由: `Overlay_Pause` の「つづける」で出す短縮カウントダウン(§6.2)の間、`Phase` は**ポーズ前のフェーズ(`Play` / `Prompt` / `Intro` など)のまま**で `Countdown` に変わらないため。`Phase` を条件にすると、復帰時のカウントダウンが何も表示されない。
- **★ポーズ復帰の短縮カウントダウンだけは、ポーズ中(`IsPaused == true`)でも進める。**「つづける」の間はポーズを解除しないまま数えるため(§6.2 の手順3)。それ以外のカウントダウンは、下の規則どおりポーズ中は進めない。
- **★ポーズ中は進めない。**現在の `PlayCountdownSteps` は `WaitForSecondsRealtime` で待っており、**ポーズ(`SetPaused(true)`)しても待ちが進んでしまう**。`[Prompt]` と同じく「ポーズでないフレームだけ経過時間を足す」形に直すこと。
- **合計の待ち時間は `countdownNormal` / `countdownRetry` を厳密に守る**(表示のためにずらさない)。

## 5. 背後に何が見えるか・重なり順(★2026-09-17 整理)

### 5.1 背景を暗くしない方針

- **`Blocker` の alpha は 0。背後の画面をそのまま見せる。**
- 理由: **HUD(90秒バー満タン・件数0)と画面の状態を見せたまま、再開・開始の心構えを作る**ため。
  (2026-09-07 当初の理由「カウントダウン中に問題を読み始められる」は、2026-09-15 の「業務提示が終わるまで問題を見せない」決定で失効した。§5.2 のとおり、問題が見えるのは「操作中にポーズして復帰する」ときだけ)
- **`Overlay_Pause`(`Blocker` alpha 0.75)との差は意図的**(ポーズ中は背後を隠して「ポーズ中に考える」を防ぐ)。

### 5.2 状況ごとに背後に見えるもの

| 状況 | `PromptBackdrop`(黒) | 背後に見えるもの |
|---|---|---|
| **セッション開始**(Title の開始ボタン) | **非表示**(★ミニゲームがまだ無いので隠すものが無い。`[Prepare]` はカウントダウンの後) | `Screen_GamePlay` の背景 / HUD(**ミニゲーム名は空欄**・件数0・コンボ非表示・90秒バー満タン)/ 12秒バーは空 / 進捗ドットは全部空 / **空のミニゲーム領域** |
| **「もう一回」**(Result) | 非表示 | 同上(画面が新しく作られる) |
| **ポーズの「はじめから」** | **非表示にする**(★ポーズ前が `[Prompt]` / `[Intro]` なら黒が出ていたので、`StartSession` で消す) | 同上。**HUD も初期状態に戻す**(件数0・コンボ非表示・90秒バー満タン・ミニゲーム名は空欄・ドットは空) |
| **ポーズの「つづける」—— `[Play]` 中にポーズした** | 非表示 | **操作中の問題と HUD**(ポーズ前と同じ。もともと見えていた問題なので隠さない) |
| **ポーズの「つづける」—— `[Prompt]` / `[Intro]` 中にポーズした** | **表示のまま** | **黒い背景**(問題は見えない。業務提示の文字は初期状態で非表示)と HUD |

**セッション開始時の流れ(見た目)**

```
開始ボタン
  → GamePlay の背景 + HUD の上に「3」「2」「1」「スタート!」(3.0秒。背景は明るいまま)
  → 「スタート!」がフェードアウトした次の瞬間(同じフレーム)に [Prepare]: 黒い PromptBackdrop で覆う
  → [Prompt] 黒背景にゲーム名(1.5秒・merry.wav)
  → [Play] 黒を消して問題を見せる(ハードカット)
```

- **明るい画面 → 黒 → 問題、と2回切り替わる。**業務提示の「黒 → 問題のハードカット」と同じ系統の切り替えなので許容する(変えたい場合は §8-7)。
- **★実装の現状との差(要対応)**:
  - HUD のミニゲーム名 `MicroGameNameText` は Prefab の仮文字「ミニゲーム名」のまま出る(`GamePlayScreenController.OnEnable` が空にしていない)→ **カウントダウン中は空欄にする**。
  - 進捗ドットは `[Prepare]`(`HandleMicroGamePrepared`)でしかリセットされない → **画面に入ったとき・セッション開始時にも空にする**。
  - 「はじめから」で HUD と `PromptBackdrop` を初期状態に戻す処理が無い → **セッション開始(`StartSession`)のたびに戻す**。

### 5.3 重なり順(手前ほど下)

```
[奥]  ScreenLayer
        Screen_GamePlay
          SafeAreaRoot
            Background
            HudRoot(ミニゲーム名・件数・コンボ・ポーズボタン・90秒バー)
            ContentRoot
              MicroGameSlot(ミニゲーム)
              PromptBackdrop(黒)/ PromptRoot(業務提示の文字)
              12秒バー・進捗ドット など
            FinishRoot(終了演出。カウントダウンと同時には出ない)
            BottomReserve
[手前] OverlayLayer
        Overlay_Countdown

```

- **`Overlay_Countdown` は `OverlayLayer` の子なので、`Screen_GamePlay` のすべての要素(HUD・`PromptBackdrop`・業務提示の文字)より手前に描かれる。**Prefab 内の並び順を工夫する必要はない。
- **カウントダウンと業務提示の文字は同時に出ない**(`[Prompt]` はカウントダウンの後。ポーズ復帰時は業務提示の文字を初期状態=非表示に戻してある)。
- **`Blocker` が全面を覆うので、HUD のポーズボタンはカウントダウン中タップできない**(フェーズでも非活性)。

## 6. ポーズとの関係

### 6.1 カウントダウン中にポーズした(バックグラウンド移行)

> カウントダウン中は HUD のポーズボタンが押せないので、**起きるのはバックグラウンド移行のときだけ。**

| 手順 | 処理 |
|---|---|
| 1 | **カウントダウンの進行を止める**(経過時間を足さない。§4.3) |
| 2 | `Overlay_Countdown` を閉じる(優先順位 `Pause > MicroGameIntro > Countdown`。共通仕様 §2.2)。アニメーションの値を戻す |
| 3 | `Overlay_Pause` を出す |
| 4 | 「つづける」→ **カウントダウンを最初からやり直す。長さは `Short`(1.5秒)**(セッション開始時の `Normal` 中断でも `Short` にする)。**★2026-09-17 実装は簡略化されている(§6.4)** |
| 5 | 「はじめから」→ セッションを作り直し、`Short`(1.5秒) |
| 6 | 「やめる」→ 記録せず `Screen_Title` へ |

**T1 はカウントダウン前から止まっているので、何度中断しても時間は失われない。**

### 6.2 ポーズからの復帰(「つづける」)

```
1. se_button
2. Overlay_Pause を閉じる(★先に閉じる。Pause が出ている間は優先順位で Countdown を出せない)
3. Overlay_Countdown(Short 1.5秒)を出す。背後は §5.2 のとおり
     ・この間もポーズは解除しない(T1・T2・ミニゲーム・BGM は止まったまま)
     ・HUD のポーズボタンは非活性
4. カウントダウン終了と同じフレームで:
     ・Overlay_Countdown を閉じる
     ・SetPaused(false)(T1・T2・microGame.SetPaused(false)・BGM を再開)
     ・ポーズ前のフェーズに戻る:
         [Play] → 操作を再開(ポーズボタン活性)
         [Prompt] → 業務提示を t=0 からやり直す(10 §12.7)
         [Intro] → 初出カードを再表示(31 §4.4)
         [Countdown](セッション開始のカウントダウン中にポーズした)→ 手順3のカウントダウンがそのまま開始の助走を兼ねる。
                     終わったら T1 の計測を開始し、1本目の [選定] → [Prepare] へ(Normal をやり直さない)
                     ★2026-09-17 実装はこのとおりになっていない(§6.4)
```

**★実装(2026-09-17)**: `GameSessionController.ResumeFromPause()`。
- 手順2〜3: `HideOverlay(Pause)` → `ShowOverlay(Countdown)` → Short のステップを進める(**ポーズ中でも進める**。§4.3)→ `HideOverlay(Countdown)` → `CountdownStepIndex = -1`。
- 手順4: **`[Intro]` 由来なら初出カードを再表示し、ポーズは解除しない**(カードの OK で解除される)。**`[Prompt]` 由来なら業務提示を t=0 からやり直す印を付けて `SetPaused(false)`。それ以外は `SetPaused(false)` だけ**(元の処理がその場から続く)。
- **カウントダウン中は `Phase` が変わらない**ので、オーバーレイは `CountdownStepIndex` を見て表示する(§4.3)。HUD のポーズボタンは `IsPaused` が true のままなので押せない。

### 6.3 「はじめから」

```
1. se_button
2. Overlay_Pause を閉じる
3. StartSession(mode, retry: true)
     ・現在のミニゲームを破棄、セッション状態を初期化
     ・PromptBackdrop を消し、HUD を初期状態に戻す(§5.2)
     ・Overlay_Countdown(Short 1.5秒)
```

> ~~**★2026-09-17 時点の実装**: `Overlay_Pause` は未作成で、HUD のポーズボタンが `SetPaused` を直接切り替えている(再開時のカウントダウンは無い)。~~
> ~~**本節は `Overlay_Pause` を実装するときに合わせて作る。**暫定のポーズボタンから再開する場合も、できれば同じ「Short カウントダウン → 再開」の経路を通すこと(developer 判断)。~~
> **★2026-09-17(3): `Overlay_Pause` を実装済み。**HUD のポーズボタンはトグルをやめ、ポーズに入るだけになった。**再開は必ず「つづける」→ Short カウントダウン → 再開の経路を通る。**「はじめから」は `HideOverlay(Pause)` → `StartSession(現在のモード, retry: true)`(**確認ダイアログは無し。暫定**。`31_Overlay_Pause.md` §5-2)。

### 6.4 ★`[Countdown]` 中の自動ポーズからの復帰 —— 簡略実装と仕様の差(2026-09-17)

| | 内容 |
|---|---|
| **仕様**(§6.1 手順4 / §6.2) | 「つづける」→ Short(1.5秒)を**最初から** → 終わったら**すぐ** 1本目の `[選定]` → `[Prepare]` |
| **実装** | 「つづける」→ Short(1.5秒)を表示 → `SetPaused(false)` → **ポーズで止まっていた元のカウントダウン(Normal / Short)が、止まった位置から残りを消化する。**このときオーバーレイは閉じているので**画面には何も出ない** → 1本目の `[選定]` → `[Prepare]` |
| **体感** | 「スタート!」が消えてから、**表示も音も無い間**を置いて業務提示が始まる |
| **起きる条件** | **セッション開始・「もう一回」・「はじめから」のカウントダウン中に、アプリを裏へ回した(または Editor でフォーカスを外した)ときだけ。**手動のポーズボタンはカウントダウン中は押せないので起きない |
| **T1** | カウントダウン中は T1 が動かないので、**時間は失われない** |

**★間の長さについて(開発チームに確認が必要)**
- developer の報告は「**最大1ステップ分**の無音・無表示の間が入ることがある」。
- プランナーがコードを読んだ限りでは、元のカウントダウンは**止まったステップの残りに加えて、その後のステップもすべて**表示なしで消化するように見える。そうだとすると、**セッション開始(Normal: 0.75秒 × 4)の「3」の途中で裏へ回した場合、約2.5秒の間**になりうる(「もう一回」「はじめから」の Short なら最大約1秒)。
- **さらに、`se_countdown` / `se_start` の素材を登録すると、この「表示の無い間」にカウントダウンの音だけが鳴る**ように読める(現在は素材が無いので無音)。
- **素材を登録する前に、developer に実際の長さと音の挙動を確認すること**(§8-11)。

**仕様どおりにする場合の方向性(実装方法は developer 判断)**: 「つづける」の時点で、中断していた元のカウントダウンを**打ち切り済み**として扱い、短縮カウントダウンが終わったら直接 1本目へ進める。
