## 1. 目的

**「これから始まる」という心構えを作り、指を画面に近づけさせる。**

90秒という短いセッションで、**開始直後の1問を取りこぼさせないための助走**である。
長いと「もう一回」のテンポを殺すので、**リトライ時は半分に短縮する。**

### 1.1 出る場所 / 出るタイミング

- `OverlayLayer` に `Instantiate` される(共通仕様 §2.2)。**`Screen_GamePlay` の Prefab には含めない。**
- **`Screen_GamePlay` に入った直後、セッションタイマー(T1)が動き出す前。**
- **`Overlay_Pause` の「つづける」からの復帰時**にも使う(短縮版)。

| # | 呼び出し元 | 長さ | 内容 | ステップの長さ |
|---|---|---|---|---|
| `Normal` | **`Screen_ModeSelect`** から開始 | **3.0秒** | 3 → 2 → 1 → スタート! | 0.75秒 × 4 |
| `Short` | **「もう一回」から開始** | **1.5秒** | **2 → 1 → スタート!** | 0.5秒 × 3 |
| `Short` | **ポーズからの復帰** | **1.5秒** | **2 → 1 → スタート!** | 0.5秒 × 3 |
| ~~`Minimal`~~ | ~~`Overlay_MicroGameIntro` の OK 後~~ | ~~1.0秒~~ | ~~1 → スタート!~~ | **★2026-09-15 廃止** |

> **★既存文書は「リトライ時は1.5秒に短縮」としか書いておらず、
> 「3・2・1 が1.5秒に入らない」ことに触れていなかった(§5-1)。**
> 本書は **カウントの数を減らす**ことで、1ステップあたりの長さを確保する方式を採る。

> ~~【2026-09-07 追加】初出カードの OK 後に `Minimal`(1.0秒)が加わった。~~
> **【2026-09-15 ディレクター決定】`Minimal` を廃止した。初出カードの OK を押したら、カウントダウンを挟まずすぐ業務提示に入る。**
> **理由**: 業務提示が 0.8 → 1.5秒になり、ショート動画風の強い演出が付いたことで、**業務提示そのものが助走になった**。
> 残すと OK から操作開始まで 1.0 + 1.5 = 2.5秒の二重の助走になる。業務提示中は入力を受け付けないので、指を画面に戻す時間もそこで確保できる。
> (2026-09-07 の採用理由「二重の助走を避ける」を突き詰めた結果、カウントダウン側を削った。経緯は決定ログ §4-6)

> **【2026-09-15 追記】**
> - **ポーズからの復帰(`Short`)で、ポーズに入ったのが業務提示の途中だった場合は、カウントダウン終了後に業務提示を最初からやり直す。**
> - **「スタート!」(`se_start`)の直後に1本目の業務提示(`se_microgame_start`)が鳴る。**「スタート!」のステップ(0.75秒 / 0.5秒)の中で `se_start` が鳴り終わるよう、`se_start` は0.5秒以内の素材にすること。

### 1.2 ★実装は「ステップの配列」を渡す形にする

**3通りの呼び出しがあるが、Prefab は1つで足りる。**(★2026-09-15 `Minimal` 廃止で4 → 3通り)

```csharp
public enum CountdownPreset { Normal, Short }   // ★Minimal は削除(2026-09-15)

// GameBalanceSettings に持たせる(仮値)
Normal  : 表示するキーの配列 ["3", "2", "1", "start"]  / 1ステップ 0.75秒
Short   : ["2", "1", "start"]                          / 1ステップ 0.5秒
```

> 実装の現状: `GameBalanceSettings` には `countdownNormal` / `countdownRetry` の2種しか無く、`Minimal` も `CountdownPreset` も**コードに存在しない**。
> また `GameSessionController` は初出カードを閉じた後にカウントダウンを出していない。**つまり現状のコードは新仕様どおりで、削除すべきコードは無い。**
> **`Minimal` を今後追加しないこと。**

- **表示する文字列の配列と1ステップの長さ**を渡すだけにする。
- **12月に新しい長さが必要になっても、SOに1行足すだけで済む。**
- **`GameBalanceSettings` で各プリセットを調整可能にすること。**

## 2. Prefab構造(初回生成時)

```
Overlay_Countdown                         stretch(OverlayLayer に出す)
├─ [CountdownOverlayRefs]
├─ [CountdownOverlayController]
├─ Blocker                                Image alpha 0 / stretch / raycastTarget = true
└─ CountRoot                              anchor(0.5,0.5) / 800×800
    ├─ CountText                          「3」/「2」/「1」/「スタート!」
    └─ CountRing                          Image(数字の背後の輪。任意)
```

- **`Blocker` は透明だが `raycastTarget = true`。** カウントダウン中のタップを完全に遮断する。
  **これがないとカウントダウン中のタップがミニゲームに届いてしまう。**
- **画面を暗くしない**(`Blocker` の alpha は 0)。
  ~~背後のミニゲームがすでに見えていることが重要で、カウントダウン中に問題を読み始められる。~~
  **★2026-09-15 改訂: 「業務提示が終わるまで問題を見せない」決定(`10_Screen_GamePlay.md` §12.6)により、この理由は失効した。**
  セッション開始時はまだ `Prepare()` 前でミニゲームが無く、業務提示中・初出カード中にポーズした後の復帰では `PromptBackdrop` が問題を覆ったまま。
  **問題が見えるのは「操作中にポーズして復帰する」ときだけ**(もともと見えていた問題なので扱いは変えない)。暗くしない理由は「HUD と画面の状態を見せたまま再開の心構えを作る」に置き換える。

### 2.1 レイアウト初期値(**以後ディレクターの所有物**)

| 要素 | anchor / pivot | anchoredPosition | sizeDelta |
|---|---|---|---|
| `Blocker` | stretch | — | 全面 |
| `CountRoot` | (0.5,0.5)/(0.5,0.5) | (0, 0) | (800, 800) |
| `CountText` | (0.5,0.5)/(0.5,0.5) | (0, 0) | (800, 400) |

**文字サイズの初期値: 400px**(業務提示の180pxより大きく。画面の主役になる)。

## 4. 処理内容

### 4.1 タイムライン

**通常版(3.0秒)**

| 時刻 | 表示 | SE |
|---|---|---|
| 0.00 〜 0.75 | **3** | `se_countdown` |
| 0.75 〜 1.50 | **2** | `se_countdown` |
| 1.50 〜 2.25 | **1** | `se_countdown` |
| 2.25 〜 3.00 | **スタート!** | `se_start` |

**短縮版 `Short`(1.5秒)**

| 時刻 | 表示 | SE |
|---|---|---|
| 0.00 〜 0.50 | **2** | `se_countdown` |
| 0.50 〜 1.00 | **1** | `se_countdown` |
| 1.00 〜 1.50 | **スタート!** | `se_start` |

~~**最短版 `Minimal`(1.0秒)—— 初出カードの OK 後**~~ **★2026-09-15 廃止。**初出カードの OK 後はカウントダウンを出さず、すぐ業務提示(1.5秒)に入る(§1.1)。

> **どのカウントダウンでも T1 はもともと止まっている**(セッション開始前 / ポーズ中)。

各ステップの演出: **0.1秒でスケールイン(1.3倍 → 1.0倍)→ 静止 → 最後の0.1秒でフェードアウト。**

### 4.2 前後の処理

```
[表示前]
  ・GameSessionController が Screen_GamePlay の初期化を終えている
  ・★最初のミニゲームの Prepare() はまだ呼ばれていない(共通仕様 §4.3 の順序)
  ・T1(90秒)は停止したまま
  ・HUD は初期状態(件数0 / コンボ非表示 / T1バー満タン)で表示されている

[表示中]
  ・T1 は動かない(★0秒も消費しない)
  ・入力は Blocker が完全に遮断する

[終了時]
  ・Overlay_Countdown を Destroy
  ・GameSessionController が T1 の計測を開始
  ・最初のミニゲームの [選定] → [Prepare] へ進む
```

> **「スタート!」の表示中も T1 は動いていない。** 90秒はカウントダウン終了後に始まる。
> **`Overlay_Countdown` は 90秒の外側にある。**

### 4.3 中断されるケース

| ケース | 処理 |
|---|---|
| **バックグラウンドへ移行した** | **カウントダウンを中断し、`Overlay_Countdown` を閉じて `Overlay_Pause` を出す**(共通仕様 §2.2 の優先順位 `Pause > MicroGameIntro > Countdown`)。復帰後「つづける」を押したら**カウントダウンを最初からやり直す**(短縮版1.5秒) |
| アプリ終了 | 何もしない |
