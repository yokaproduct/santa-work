## 3. 新設した3つの仕組み

### 3.1 ② のための `Part_UnitProgressDots`(共通仕様 §6.5)

**問題**: M1・M2・M3 には「いま何件目か」を示すものが画面上に**何もない**。
プレイヤーは3問答えたらミニゲームが終わることを、**プレイからは学べない**。
(M5だけはループ進行ドットを持つが、これは種目固有の仕組みだった)

**解決**: **3つのドット(●●○)を全種目共通で `Screen_GamePlay` の差し替え領域の上に置く。**

- `OnUnitCleared` のたびに1つ埋まる。**3つ埋まればクリア**が視覚的に自明になる。
- **`Screen_GamePlay` が持つ**(`Part_MicroGameTimerBar` と同じ扱い)。ミニゲームPrefabには置かない。
- **M3の `SledProgressText`(「そり 2 / 3」)は廃止し、この共通ドットに一本化する。**
  種目ごとにバラバラの進捗表示を持つのをやめる。
- **M5のループ進行ドット(`LoopDot`)は別物なので残す**(ループ内3箱の進捗)。M5だけドットが2段になる。

### 3.2 ③ のための `Part_ScorePopup`(共通仕様 §6.6)

**問題**: プランナーは共通仕様 §6.1 で「**HUDにスコア数値を置かない**」ことを提案していた。
**チュートリアルがあった前提では成立していたが、廃止された今、
「コンボが乗ると点が増える」ことを知る手段が画面上から完全に消える。**

**解決**: **件が成立するたびに、獲得点を短く浮かび上がらせる。**

```
コンボ 1 → 「+100」
コンボ 3 → 「+120」   ← コンボ表示が出るのと同時に数字が増える
コンボ 10 → 「+200」
```

- **「コンボ表示が出た」と「もらえる点が増えた」が同時に起きる**ため、因果が1回で伝わる。
- 0.4秒でフェードアウトする非ブロッキング演出。**ゲームを止めない。**
- **HUDに常設のスコア表示を置く案の代替。** どちらか一方でよい(§5-2 でディレクター判断)。

### 3.3 ④ のための「初出カードの共通1行」+ 判定演出の制約

**問題**: ④は**プレイからは絶対に学べない。**
時間切れになっても何も悪いことが起きないが、**「起きなかった」ことに気づくのは難しい**
(コンボは3以上でしか表示されないため、コンボ2で時間切れになっても変化が見えない)。

**さらに悪いのは、プレイヤーが逆に学習してしまうこと。**
「時間切れは損だ」と思い込むと**当てずっぽうで押す**ようになり、
これは設計が最も避けたい行動(「誤答のほうが重いので、慎重さが報われる」)の正反対になる。

**解決(2つ併用)**

1. **初出カードの本文に、全4種共通の1行を入れる。**
   ```
   わからない ときは とばして いい。
   ```
   - 4種すべてのカードの最終行に置く。**種目固有の説明の後に、全体ルールを1行だけ添える。**
   - **初出カードが全体ルールを運ぶ唯一の場所**になる。
2. **判定演出(中身は保留)への制約を1つ追加する。**
   ```
   時間切れで終わったとき、「失敗ではない」と分かる表現にすること。
   誤答時の表現と明確に区別すること。
   ```
   - 共通仕様 §3.8 の制約リストに追加済み。
