## 1. 目的 / この種目の役割

**そりの目標の数値ちょうどになるように、6個の箱から組み合わせを選んで積む。**
(★2026-09-16: 目標の数値は、そりの画像の上ではなく**そりと箱の間**に出す。§3.3)

- 使う知識: 算数(加算・組み合わせ探索)
- 業務提示ワード: **「はかれ!」**(`micro.weight.prompt`)
- 操作: **箱をタップして複数選択(★最大3個まで。2026-09-16)。もう一度タップで取り消せる。確定ボタンは置かない**
- 1件 = そり1台(`questionsPerUnit = 1`)。**1ミニゲームでそり3台をさばく**

**単位は付けない。数値だけを表示する。** 国によって使う単位が違う(kg / ポンド)ため。
**この決定により M3 の翻訳は実質ゼロになる。**

**難易度は設計しない。** 同じ「合計13」でも、最初に選んだ箱がたまたま解に含まれていれば一瞬で終わり、
外していれば取り消してやり直す。**プレイヤーの試行順序という制御できない要素が、そのまま難易度のばらつきになる。**

### 1.1 この種目の既知の弱点(設計原則5から最も遠い)

**M3は4種で最も説明を要する。** 説明が要りそうな点は4つ:
①合計を目標値**ちょうど**にする ②**複数選べる(★最大3個。2026-09-16)** ③**取り消せる** ④オーバーしても続けられる。
**積載メーターが①を視覚化するが、②③は絵で伝わりにくい。**

**複数選択はM3の中核(合計を作る遊び)なので削れない。演出で伝えるのが現実的。**
本書が採る打ち手は次の3つ。

| 打ち手 | どこで実現するか |
|---|---|
| **選んだ箱を明確に持ち上げて「まだ確定していない」と見せる** | §3.1 の選択状態。**上に浮かせる + 影を付ける** |
| **積載メーターが目標値を超えたら赤くあふれさせ「戻せる」と気づかせる** | §3.2 のオーバー表現 |
| **初出カードに「もういちど おすと もどる」の1行だけ添える** | `Overlay_MicroGameIntro` の本文(`micro.weight.introCard.body`) |

### 1.2 差し込まれる場所

`Screen_GamePlay` の `MicroGameSlot`。HUD・12秒バー・業務提示・判定演出は `Screen_GamePlay` 側が持つ。

### 3.1 箱の状態(★複数選択・取り消しを伝える要)

| 状態 | 見た目 | 意味 |
|---|---|---|
| 未選択 | 既定 | まだ積んでいない |
| **選択中** | **上に浮かせる(持ち上げる)+ `BoxShadow` を出す + ハイライト枠** | **「まだ確定していない」ことを示す。**これが「もう一度押せば戻せる」というメッセージになる |
| 非活性 | 見た目は変えない | `Begin()` 前 / `Finish()` 後 / ポーズ中 / そりのスライド演出中 |

> **★2026-09-16 ディレクター決定: 選択中の箱が3個あるとき、未選択の箱(4個目)をタップしても受け付けない。**
> - 選択状態・合計・メーター・そり画像は**何も変えない**。**ペナルティなし**(`OnMissed` を発火しない。コンボも切らない)。
> - **SE も鳴らさない**(`se_tap` を含む。「受け付けていない」ことと合わせるための暫定。§8-12)。
> - **`Button.interactable` は変えない**(未選択の箱を非活性の見た目にしない)。タップを受けたうえで、コード側で無視する。
> - **選択中の箱のタップ(取り消し)は3個選択中でも通常どおり受け付ける。**
> - 正解は常に2〜3個の組み合わせなので(§5)、**上限3個で解けない問題は存在しない。**

> **「浮かせる」演出は `RectTransform.anchoredPosition` を実行時に動かすことになる。**
> これは**実行時のみの一時的な変化であり、Prefabアセットを書き換えない**限り所有権ルールに反しない。
> ただし**元の位置を保存して必ず戻すこと**(共通仕様 §7.4 と同じ考え方)。
> **代替として `localScale` や子オブジェクトのオフセットで表現する方法もある。実装方式は開発チーム判断(§9-M3-4)。**

### 3.2 積載メーターの表現

| 状態 | 表現 |
|---|---|
| 合計 < 目標値 | `MeterFill` が合計の位置まで伸びる。`MeterTargetLine` はその先にある |
| **合計 = 目標値** | **成立。**そりが右へ抜ける |
| **合計 > 目標値** | **`MeterOverflow` が赤くあふれる + `SledReindeerImage` が怒り顔の画像(`weight_angry{n}`)になる**(★2026-09-16: 旧「トナカイが悲しい表情」を置き換え)。**ゲームは止まらない** |

**メーターの最大値**: 6個すべての合計。**目標値ではない**(オーバーを表現できる必要があるため)。
`MeterTargetLine` の x 位置 = `目標値 ÷ 6個の合計 × メーター幅`。

> **★2026-09-16 注記**: 選択が最大3個になったため、**メーターが満タンになることは無くなった**(3個の合計 < 6個の合計)。
> 最大値を「数値の大きい3個の合計」に変えるかは §8-13 で判断待ち。**変更が決まるまでは現行どおり6個の合計とする。**

### 3.3.1 ★目標の数字の表示(2026-09-16(3) ディレクター決定)

> **目標の数字 `TargetValueText` は、そり(`SledPanel`)と箱の選択エリア(`BoxGrid`)の間に表示する。数字だけを出し、文章(「めざす おもさ」等)は付けない。文字色は黒。**

**変更の理由**: そりの画像(仮画像は白地)の上に重ねると、数字が背景と同化して読みにくかった(ディレクター指摘)。
あわせて、統合画像を比率を保って表示すると約480×270に縮み(§8-11)、**車体の上に数字を置く場所が小さくなる**問題も解消する。

**動き方(★プランナー推奨方針。developer へ伝達済み・実装済み)**

> **★実装(2026-09-16)**: 数字の差し替えは既存の `SetupUnit` の呼び出し(次のそりが入るフレーム)で行われており、下表の要件を満たしていた。
> **`SetupUnit` は目標値と箱の数値をまとめて設定するので、下の「目標の数字と箱の数値の差し替えがずれる」心配は実装上は起きない。**

| 時点 | `TargetValueText` |
|---|---|
| `Prepare()`(1台目の準備) | 1台目の目標値を入れる(`PromptBackdrop` で隠れている) |
| そり1台が成立 → 前のそりが右へ抜けるまで | **成立した目標値のまま**(喜び顔のそりと数字が合っている) |

- **`SledUnit` のスライドに付いていかない。**`TargetValueText` は `SledUnit`(および `SledTrack` のマスク)の外に置き、**位置は常に固定**。コードは数字の中身だけを変え、**RectTransform を動かさない。**

- 文字色の黒は、数字の下に来る背景(いまは `Screen_GamePlay` の `Background`。将来は工場背景 IMG-BG-02)との組み合わせで決めた。**背景素材を差し替えたら見直す**(共通仕様 §7.7)。

### 4.3 箱をタップしたとき(★この種目の中核)

```
0. ★2026-09-16: その箱が未選択 かつ 選択中の箱がすでに3個 → 何もしないで終わる
   (SEなし・見た目の変化なし・OnMissed なし。§3.1 の注記)
1. se_tap を再生
2. その箱の選択状態をトグルする
   ・未選択 → 選択中(浮かせる + 影 + ハイライト)
   ・選択中 → 未選択(元に戻す)
3. 選択中の箱の合計を再計算し、MeterFill を更新する
4. 合計を判定する(n = 選択中の箱の数)
   ・合計 == 目標値 → 成立(§4.4)。SledReindeerImage を weight_happy{n} に
   ・合計 >  目標値 → MeterOverflow を出す + SledReindeerImage を weight_angry{n} に(★旧: トナカイを悲しい表情に)
                      ★OnMissed を発火しない。コンボは切らない。ゲームは止まらない
   ・合計 <  目標値 → MeterOverflow を消す + SledReindeerImage を weight_normal{n} に
                      (n = 0 なら weight_sled_reindeer)
```

> **選択数の上限(3)は、実装ではコード上の定数**(`WeightMicroGame.MaxSelectedBoxes = 3`)。**Inspector では変えられない。**
> **正解の箱の数も3個を超えないよう、生成器側で定数(`WeightQuestionGenerator.MaxAllowedAnswerBoxCount = 3`)で必ず抑える**
> (`answerBoxCountMax` が誤って3より大きく設定されていても3に丸める)。上限を変えるときは両方の定数をそろえること。

> **★M3のオーバーは契約上の「誤答」ではない。**
> やり直せる以上、他種目の誤答とは性質が違う。**`OnMissed` を絶対に発火しない**(共通仕様 §3.4)。
> 結果として **M3ではコンボが切れる場面が実質なくなる。**
> トナカイの表情だけが「いま失敗した」ことを伝える。

**確定ボタンは置かない。** 合計が一致した瞬間に自動判定する。

### 4.4 そり1台が成立したとき

```
1. se_sled を再生(SledReindeerImage は §4.3 で weight_happy{n} になっている)
2. OnUnitCleared を発火する
3. そりのスライド演出(★happy の画像のまま抜ける)
   ・SledUnit が右へスライドして画面外へ抜ける
   ・左から次の SledUnit が入ってくる
     ★2026-09-16(3): 次のそりが入り始めるフレームで TargetValueText を次の目標値に差し替える
       (TargetValueText 自体は動かさない。§3.3.1)
     ★実装: 抜け切った瞬間に SetupUnit(下の手順5の内容)をまとめて行い、次のそりを左から入れる
   ・★この間、全箱を非活性にする(演出中のタップを受け付けない)
4. 3台目だった場合 → OnAllUnitsCleared を発火して終了(スライド演出は不要)
5. 3台目でない場合(★実装では手順3の途中で SetupUnit として実行される)
   ・次の問題をセットアップ(目標値・6個の数値・MeterTargetLine の位置)
   ・★全箱の選択状態をリセットする(そり3台をまたいで選択状態を持ち越さない)
   ・MeterFill を 0、MeterOverflow を消す、SledReindeerImage を weight_sled_reindeer に(★2026-09-16)
   ・★進捗表示の更新は不要(OnUnitCleared を受けた Screen_GamePlay 側が自動で行う)
   ・全箱を活性化
```

> **【2026-09-07 ディレクター決定】スライド演出は 0.25秒。**(`WeightGeneratorSettings` で調整可能に)
> **演出中もタップを受け付ける案は不採用。**演出中は全箱を非活性のままとする。
> **この0.25秒の間もミニゲームタイマー(T2)は動き続ける**(共通仕様の契約上、T2を止める手段はない)。
> **1回のM3で最大3回発生する**ので、**損失は 0.75秒。M3の実質操作時間は約11.25秒。**

### 5.2 生成のバリデーション(**2条件のみ。確定**)

| # | 条件 | 理由 |
|---|---|---|
| **1** | **目標値ちょうどになる組み合わせが、6個の箱の中にちょうど1通りだけ存在する** | **正解の一意性。**複数の解があると「合っているのに違う組み合わせで正解になった」という不明瞭さが出る |
| **2** | **同じ数値の箱が2つ以上存在しない** | 見分けがつかない箱があると混乱する。また解が複数になりやすい |

**実装**: 6個の箱の部分集合は 2^6 − 1 = **63通り**。全通り試して合計が目標値になるものが**ちょうど1つ**かを確認する。
計算量は問題にならない。

**★2026-09-16 実装(`WeightQuestionGenerator`)**: **先に答えの箱を決め、残りの箱(おとり)を後から埋める方式**に変えた。
旧方式(6個を先に決めてから答えを選ぶ)では `valueMax`(35)がそのまま目標値の上限になってしまうため。

```
generate():
  for retry in 0..maxRetry:
      answerCount = answerBoxCountMin〜Max からランダム(★定数3で必ず丸める)
      answer = 相異なる answerCount 個を [valueMin, maxTargetValue] から選ぶ。合計が maxTargetValue 以下になるまで試す
               (作れなければこの retry は捨てる)                         ← ★目標値20以下を構造的に保証
      target = sum(answer)
      values = answer + 残りの箱を [valueMin, valueMax] から相異なる値で埋めて6個にする   ← 条件2を構成的に満たす
      count = 63通りのうち合計が target になるものの数
      if count == 1: return (values, target)
  return fallbackPreset     ← ★必ず返す。無限ループにしない(未設定なら presets[0])
```

> **一意性の数え方は変えていない。** 選べるのは最大3個だが、**4個以上の組み合わせも含めた63通りで「ちょうど1通り」**を確認する
> (厳しめだが、上限を後で変えても問題が壊れない)。
> **おとりの箱は `valueMax`(35)まで出る**ので、目標値より大きい箱(一目で除外できる箱)が混ざりやすい(§8-14)。

> **`Prepare()` の中で3台ぶんを1フレームで生成する。**
> 63通り × 3台 × リトライ = 最悪でも 63 × 3 × 50 = 9,450回の加算。計算量としては軽いが、
> **実機で1フレーム内に完了することを計測すること**(§9-M3-1)。
