## 1. 画面の目的

> **この画面の主役は「もう一回」ボタンである。**

企画書 §1.2 の終了時の内心は「**もう一回やって自己ベスト更新したい**」。
スコアやランクの表示はそのための燃料であって、目的ではない。
したがって設計基準は次の3つ。

1. **結果画面到達からリトライ開始までを 3秒以内に収める**
2. **スコアのカウントアップは 1.2秒以内。演出中でも「もう一回」を押せる**
3. **「もう一回」は最下部・最大サイズ**(親指が自然に届く位置)

### 1.1 遷移元 / 遷移先

| | 画面 | 条件 |
|---|---|---|
| 遷移元 | `Screen_GamePlay` | **セッションタイマーが0になった(正常終了)のみ。★2026-09-15: `Screen_GamePlay` の終了演出「しゅうりょう!」(1.5秒)が終わった直後に遷移してくる**(`10_Screen_GamePlay.md` §13) |
| **遷移先** | `Screen_GamePlay` | **「もう一回」→ タイトルを経由しない。カウントダウンは1.5秒**(「2・1・スタート!」を表示。★2026-09-17 決定) |
| **遷移先** | **`Screen_Title`**(★2026-09-17。ホーム画面) | **「やめる」**(2026-09-07 に「タイトルへ」→「やめる」/ `Screen_ModeSelect` へ変更 → **2026-09-17 に ModeSelect が Title に統合されたため `Screen_Title` へ**) |

> **【2026-09-07 決定】「タイトルへ」の遷移先を `Screen_ModeSelect` に変更し、ラベルを「やめる」にした。**
> **理由**: `Screen_Title` が機能を持たなくなった(ロゴとデザインだけ)ため、
> そこへ戻すと**「何も無い画面を経由して、さらに1タップして `Screen_ModeSelect` へ行く」**ことになり、
> 1プレイ90秒のゲームで毎回1タップの摩擦が発生していた。
> **`Screen_ModeSelect` へ戻せば、ハイスコアがすぐ見え、次のプレイにも1タップで入れる。**
>
> **【2026-09-17】`Screen_ModeSelect` は `Screen_Title` に統合された。**上の理由(ハイスコアがすぐ見え、次のプレイに1タップで入れる)は、**統合後の `Screen_Title` でそのまま満たされる。**ラベルは「やめる」のまま。

> **`Overlay_Pause` からの中断ではここへ来ない。** 中断時はスコアを記録せず ~~`Screen_ModeSelect`~~ **`Screen_Title`** へ直行する
> (共通仕様 §2.4)。**したがってこの画面に表示されるのは常に「90秒を完走した結果」だけ。**

### 3.2 ★種目別成績 —— M3の「分母 = 分子」問題への対応

**前回の指摘(共通仕様 §15.1-25)がここで効く。**
**M3は構造上 `OnMissed` をまったく発火しないため、`UnitsMissed` が常に 0 になる。**
種目別成績を「◯/◯ 件 成功」の形で出すと、**M3だけ常に 100% と表示される。**

| 案 | 表示 | 問題点 |
|---|---|---|
| A. 「◯/◯ けん」で統一 | 「よみ 5/7」「つみ 6/6」 | **M3だけ常に分母 = 分子。**「M3が一番うまい」という誤った印象を与える |
| B. 種目ごとに書式を変える | M3だけ「つみ 6けん」 | **書式が揃わず、比較しづらい。**種目追加のたびに分岐が増える(12月アップデートで破綻) |
| **C. 全種目「◯けん」に統一(★2026-09-07 承認・確定)** | 「よみ 5けん」「ちり 3けん」「つみ 6けん」「しわけ 3けん」 | 誤答数が見えなくなる。**ただし全体の正解率は R6 で別途出している** |

## 4. 処理内容

### 4.1 画面に入ったとき

```
1. GameSessionController から SessionResult を受け取る
   (score / rank / clearedUnits / missedUnits / maxCombo / 種目別内訳 / isNewRecord)
   ★セーブへの書き込みは Screen_GamePlay 側で完了している(★2026-09-15: 終了演出の t≥0.25秒で保存済み。共通仕様 §10)。
     この画面は書かない。isNewRecord も渡された値をそのまま使う(再比較しない)
2. BGM を bgm_result に切り替える(★GameSessionController が遷移の直前に開始済み。同じIDなので二重に呼んでも頭出しされない。
   直前の終了演出中は無音なので、ここで曲が始まる)
3. AdDisplayPolicy に従いバナーを表示する(★この画面は表示する)
4. RankBadgeImage / RankNameText を設定して登場演出(se_rank)
5. NewRecordBadge を alpha 0/1 で切替(isNewRecord なら se_newrecord)
6. StatsPanel / MicroGameScoreRow を設定
7. ScoreValueText のカウントアップを開始(§4.2)
8. RetryButton / QuitButton を活性化(★カウントアップの完了を待たない)
```

### 4.2 スコアのカウントアップ

| 項目 | 値 |
|---|---|
| 長さ | **1.2秒以内**(`GameBalanceSettings` で調整可能に) |
| 開始値 | 0 |
| 終了値 | 最終スコア |
| **スキップ** | **`RetryButton` / `QuitButton` を押した時点で即座に最終値へ確定**(演出を待たせない) |
| 画面タップ | **カウントアップ中に画面のどこかをタップしたら即座に最終値へ確定**(§7-3) |

> **カウントアップ中でもボタンを押せることは仕様。** 押されたら演出を完了状態にしてから遷移する。
> **「演出が終わるまで押せない」実装にしてはならない**(企画書 §7.4)。

### 4.3 各要素を操作したとき

| 要素 | 操作 | 処理 |
|---|---|---|
| `RetryButton` | タップ | ① `se_button` ② カウントアップを即完了 ③ `Screen_Result` を破棄 ④ **`Screen_GamePlay` へ直行**(`retry = true` → カウントダウン **1.5秒**)⑤ BGM を `bgm_gameplay` へ ⑥ バナーを非表示に |
| `QuitButton` | タップ | ① `se_button` ② カウントアップを即完了 ③ **`Screen_Title` へ**(★2026-09-17。旧 `Screen_ModeSelect`)④ BGM を `bgm_title` へ(最初から再生) |

> **★2026-09-17 注意: 「やめる」の2度押しで、次の画面の開始ボタンに当たる。**
> この画面の `QuitButton`(初期値: 画面下端から約 696〜816px、横400px・中央)と、`Screen_Title` の `PlayButton_Time90`(同 約 780〜1100px、横900px・中央)は**縦に約36px重なる。**
> **`Screen_Title` 側の0.3秒の入力遅延で吸収する**(`02_Screen_Title.md` §4.2)。**この画面のボタン位置は変えない**(ディレクターの所有物)。
| 画面の空白部分 | タップ | カウントアップ中なら即完了。それ以外は何もしない |

### 4.4 「3秒以内」の検算

```
結果画面の表示     0.0秒
ランク登場演出     0.0 〜 0.5秒   ← この間もボタンは押せる
スコアカウントアップ 0.0 〜 1.2秒   ← この間もボタンは押せる
プレイヤーが「もう一回」を押す  ← 最短で 0.3秒(反応時間)
画面遷移           0.2秒
カウントダウン     1.5秒
────────────────────────────
最短で 0.3 + 0.2 + 1.5 = 2.0秒 ✓  目標の3秒以内
```

**演出の完了を待つ実装にすると 1.2 + 0.2 + 1.5 = 2.9秒**となり、ぎりぎりになる。

> **★2026-09-17 決定: カウントダウン1.5秒は「2・1・スタート!」を表示する(長さは変えない)。**上の検算(最短2.0秒)はそのまま有効。
> その後に業務提示1.5秒が続くので、「もう一回」を押してから操作できるまで約3.0秒になる。**ディレクター了承済み**(`30_Overlay_Countdown.md` §0.2)。
**スキップ可にしておくことが「3秒以内」を守る鍵。**

> **★2026-09-15 注記: この画面の手前に終了演出(1.5秒)が入った。**
> 上の「3秒以内」は**結果画面の表示を起点にした計測なので変わらない。**
> 「90秒が終わってから次の1プレイが始まるまで」は **1.5 + 2.0 = 最短3.5秒** になる。
> **終了演出の間は `Screen_GamePlay` 側で全タップを遮断している**ため、プレイの最後まで連打していた指が、
> この画面の「もう一回」やバナーに誤って当たりにくくなる(§2.2 の誤タップ対策を補強する)。
